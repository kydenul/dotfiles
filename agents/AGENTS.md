# 全局规则

## 安全红线

- 密钥 / token / DSN / secret 绝不硬编码进可提交的文件（代码、yaml、文档示例）；生产经环境变量或密钥管理服务注入，可提交配置里只写 `${VAR}` 占位。
- 身份只在信任边界（网关 / 入口）注入；下游只信任边界注入的身份，必须拒绝或覆盖外部传入的同名身份头（如 `x-user-*`），且下游端口只暴露在受信内网。
- CORS：`AllowCredentials=true` 与 `AllowedOrigins=["*"]` 不得同时出现。
- 日志 / 出站请求 dump 默认脱敏（Authorization、Cookie、token）；关闭脱敏必须有明确排查理由并写进注释，排查完把日志级别调回。
- 由用户输入拼接的键（锁键、缓存键、路径）必须校验分隔符等特殊字符，防止拼出他人的键。

## 禁止主动创建 Markdown 文档

- 除非用户明确要求（如「写个 README」「生成一份文档」），不要新建任何 `.md` 文件：README、使用指南、API 文档、功能说明、设计总结都不行。
- 需要解释的内容放在对话里或代码注释里；完成功能后可以问一句「需要我写文档吗？」。
- 不受此限：更新仓库已有的文档（分层 `AGENTS.md`、`changelog.md` 等），因为它们本身就是文档体系，应扩展它而不是另起新文件。
- 用户中途取消写文档时立即停止。
